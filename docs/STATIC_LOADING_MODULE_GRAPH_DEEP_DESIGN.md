# FlowWeave 静态加载与功能模块图：统一结构和全版本迁移深化设计

状态：实施中；跨版本迁移与发布验收未完成  
日期：2026-10-02  
依据：用户指定的[原整改计划](STATIC_LOADING_MODULE_GRAPH_REMEDIATION.md)（主工作区版本状态为“待评审方案”）、实施分支同名文档的完成记录、仓库历史中的早期模块连接计划，以及当前实施分支的代码与测试  
目标：在现有 FlowWeave 上完成一次结构迁移；所有已发布旧项目经一次性迁移进入同一新协议，正常运行不保留旧 Canvas、旧生成器或旧视图的分支

## 1. 结论、边界与不可妥协的约束

原计划的方向仍然正确：新项目应先快速进入工作区并明确显示“正在分析”，随后显示证据可信、布局紧凑的功能模块图；项目打开与完整图可用分别计时。问题是当前实现只完成了局部提速和局部迁移，尚未形成单一的新系统结构。继续修补旧 Canvas 和旧执行路径会扩大状态组合，必须以一次性迁移和消费者切换为主线重新排期。

本设计覆盖项目登记、静态分析、模块归属、关系、首图、布局、视图状态、历史产物迁移，以及引用这些产物的任务、上下文、审查、序列图、Agent 和导出入口。其他功能的业务流程不在本阶段重做，但不得继续调用旧静态生成链路或读混代数据。首图只依赖本地源码静态分析；不等待 Agent、网络、项目安装或执行被分析项目脚本。规则面向受支持语言的应用、库、CLI、任务与数据项目，不以 coregist-news 或 FlowWeave 自身的目录与术语为模板。

以下五条是发布不变量：

1. 正常运行只有一个当前静态协议、一个生成入口和一个已提交代际读取入口。Canvas v1–v6 及其他旧格式只在一次性迁移器内解码。
2. 旧版中的不可重建用户信息先备份、再映射、再校验；任何未知、损坏或歧义数据都不能被空图或新生成结果静默覆盖。
3. 默认图的每条自动“调用”线仅由可定位源码位置、目标唯一确认的调用事实产生。HTTP 契约、进程调用、导入、读写与事件分别建模，不借用 calls 名称或指标。
4. 同一首图中的模块、确认关系、坐标和覆盖诊断属于同一输入指纹与生成规则版本；提交标记发布之前，渲染器不能读到半成品。
5. “完成”由跨类型真实项目的端到端性能、语义质量、旧版迁移和故障恢复证明，不能由打包成功、单项目微基准或控件数量代替。

静态分析无法普遍还原反射、动态注入和运行时注册。正确行为是报告支持范围、未解析数量及原因，不画虚假的确定关系。未知旧格式也不能承诺自动转换；它必须被保全并阻止覆盖，直到格式被识别或用户处理。

## 2. 初始实施基线与已确认根因

下表记录 2026-10-01 的实施基线，用来说明本轮整改针对的根因，不作为 2026-10-02 当前状态。当前逐阶段状态和验证证据以本文件第 9 节为准。既有文档中的“M1/M3 实现完成”只代表局部测试通过，不代表本设计的退出条件通过。

| 初始问题与证据 | 影响 | 本设计的修正 |
| --- | --- | --- |
| flowweave-store.ts 的 readExistingCanvas 对 v1–v4 返回空；现有 v4 测试还断言旧手工节点消失 | 重扫可覆盖用户编辑，违反零丢失 | 先冻结旧文件并迁移，失败不得提交新代 |
| project.ipc.ts 仍把 v5 当 legacy-readonly 运行；useProjectActions、审查与导出保留专用分支 | 新旧结构长期并存 | v5 只允许一次性导入，正常 UI 无旧版运行态 |
| canvas-migration.service.ts 的模块映射只需一个成员文件重叠 | 拆分/合并时可能把编辑贴错模块 | 仅唯一且证据充分时自动映射，歧义进入待处理 |
| project-generation.service.ts 在锁内聚类、再次扫描、准备多个产物；Agent 架构/序列入口在主进程可再次调用完整生成 | 新请求等待旧任务，主进程仍可能卡顿，出现第二写者 | 昂贵工作移到唯一 worker；锁只用于短事务；消费者只读已提交快照 |
| 重复打开只在 worker 已报告扫描指纹后才合并，并在主进程重新扫描；恢复总是启动分析，输入未变也重写 | 热开不能稳定秒进，重复请求浪费 CPU | 登记时即按项目合并；输入/规则未变则复用已提交代 |
| 静态提交仍生成任务 JSON/Markdown、上下文文件树和修改基线 | 首图被非必要工作拖慢 | 任务、上下文、Agent 及序列派生产物按需生成；迁移必要的用户基线另行处理 |
| 首图提交的 Canvas autoLayouts 为空；CanvasWorkspace 收到完整图后才运行 ELK，布局期间隐藏画布 | 当前“已提交”不代表图可点击，首屏负载大 | worker 同代生成轻量、带坐标的首图；详情按需读取 |
| static-architecture.service.ts 以目录/文件名为主要模块种子，且含 FlowWeave 专有描述；无关系的同名 api/user 与 storage/user 可误并 | 不能普适地识别具体功能 | 显式边界和语义证据优先；不足时使用中性结构范围与待判定 |
| 新增同功能的高优先级 route 文件能改变已有模块 ID | 用户坐标与跨产物引用失稳 | 稳定锚点和显式拆并 lineage，成员增减不任意换 ID |
| 聚合关系把 confirmed 与 inferred 事实合成一条 confirmed 边；HTTP/进程契约可转成 calls | 默认线的证据和含义不可信 | 逐事实保存类型、置信度和位置；仅确认的直接调用进入默认 calls |
| 功能区筛选依据 groupPath，折叠依据 domain ID；初始折叠写入的 ID 对默认 execution 视图不生效 | 同一功能区在筛选与折叠中含义不同 | 持久化唯一 areaId，导航、筛选、折叠共用 |
| 默认 execution 投影保留全部资源、测试节点；事件叠加筛选可丢失合成边界端点；覆盖率把叠加关系计入 | 首图拥挤或指标失真 | 首图仅纳入必要端点，指标只统计底层确认调用 |
| project.ipc.ts 恢复/完成时传完整 project、Canvas、Architecture；Agent context 可直接拼读多个文件且未统一校验代际 | IPC 大、首图慢，可能混代 | 单一快照读取 API 返回轻量概览与代际；详情和下游按需读取 |
| 已出现 Canvas 的 requestId/inputFingerprint 与预期不一致错误，当前提示可能导向“文件不存在/权限不足” | 用户无法区分代际竞争和文件故障 | 标记绑定读取并在切代时整体重取；报出实际代际、阶段及刷新/重试动作 |

此前对 coregist-news 的 20 次独立进程只读分析得到内存图链路 p50 2,182.9 ms、p95 2,229.2 ms，峰值 RSS p95 896 MiB。它不含原子写入、真实 ELK 拓扑、Electron IPC 和 React 首次可点击时间，且只有一个项目，不能证明“完整图秒开”。3,385 个未解析调用也说明解析覆盖诊断必须与“图准确”同时呈现。已有打包冒烟会展开分组再找边，因此不能证明默认首屏成立。该数据是单项目历史基线，不作为当前版本的发布验收结果。

## 3. 新系统的最小正式结构

复用现有 utilityProcess、语义解析、ELK 和 writeBatchAtomic 事务，不建设新调度平台或第二套事实库。用新存储协议 v7 表示**项目整体协议**，不把旧 Canvas v6 改名后继续使用。文件名是实施目标；若复用现有物理路径更简单，须保持下列逻辑边界和唯一读取契约。

| 正式产物 | 必要内容 | 所有权与读取规则 |
| --- | --- | --- |
| generation.json，storageProtocol=7 | generationId、输入指纹、分析器/规则版本、静态快照与概览哈希、提交时间 | 唯一提交标记；requestId 只用于在途协调，不作为缓存身份 |
| static-snapshot.json，schema=1 | 范围、文件/符号事实、功能区、模块、逐条关系证据、覆盖与诊断 | 唯一静态判断来源；Agent 审查不得替换它 |
| graph-overview.json，schema=1 | 同代模块/功能区摘要、默认确认调用边、全量模块基础坐标、功能区锚点、尺寸估计、计数及可见性所需最小字段 | 首屏先读此轻量文件；节点详情、证据和文件树按需读取 |
| canvas/user-state.json，schema=1 | 手工位置、节点/边、标题与说明修改、用户归属校正、查看偏好、孤立待处理项、独立修订号 | 与生成事实分离；按稳定模块/事实身份关联；用户编辑单独原子保存 |
| migration/record.json，schema=1 | 旧版本清单和哈希、备份位置、新旧映射、待处理数、尝试/失败/完成状态 | 与正式 generation 独立持久化尝试和错误；成功状态随最终切换事务提交 |
| 内部语义缓存，当前规则版本 | 增量解析所需的按文件内容事实 | 仅计算缓存；旧 Semantic Index v1–v5 经验证后可帮助迁移，但切换后不作为正式旧格式读取 |

generationId 由源码内容范围、解析配置、分析器版本和模块/图规则版本共同决定；文件 mtime/size 只能用于快速筛选，不能替代内容身份。requestId 标识一次操作，重复同输入不产生新代。静态快照、概览及其对应的用户状态在同一事务中校验后，以 generation.json 最后发布。首屏读取方在项目事务锁内恢复中断事务、读取 marker 并只核对轻量概览与用户状态的哈希/代际；大静态快照在提交时校验，详情/下游读取时再核对其哈希，不让热开为核对大文件而阻塞。不分别信任 project、Canvas、architecture 的局部版本。

首屏读取返回一致的 (generationId, userRevision) 对：先由概览投影自动模块/边和基础坐标，再叠加同修订的手工节点、边、坐标、标题、校正与待处理提示。用户编辑使用独立递增修订并经同一项目锁保存；分析 worker 不能把启动时读到的旧用户状态写回。新代提交前，在短锁内读取**最新**修订并映射；若预计算映射基于旧修订，退出锁重算后按修订号重试，最终把新快照、概览、重映射用户状态及 marker 一起发布。读者和写者都不能观察到“新图＋旧编辑”或丢失分析期间的编辑。

旧 architecture-map、Canvas 和 task/context 可以作为迁移输入或下游产物，但不再互相充当静态图的事实源。Agent 审查结论是独立建议层：用户明确采纳后写入可追踪的校正状态；下一次扫描不把 Agent 文案冒充源码证据。静态事实变更只由唯一生成链路发布。

### 3.1 打开、恢复、刷新和失败状态

1. 目录选择结束后只做路径规范化、权限/存在性检查、项目登记和最小元信息读取，立即进入可交互工作区。无当前协议项目显示“正在迁移”；新项目显示“正在分析”及阶段/覆盖进度。此处不加载完整树或 Canvas。
2. 已迁移项目可立即展示上次完整概览，但在输入核验前标“上次分析结果”。后台核对文件集合、内容哈希、解析配置、包导出/依赖绑定及规则版本；mtime/size 仅帮助找候选变更。**只有内容和依赖身份验真完成**才标“当前”并跳过重算；源变更时继续明确标旧，后台生成新代后整体切换。验真时间单独计入热开指标，不能用未验真的缓存冒充当前。
3. 同一规范路径的重复打开、恢复和刷新在**扫描前**加入同一在途任务；新输入取代旧任务时先发取消/终止，再启动新任务。按 M0 实测给全局 worker 数和内存设上限，防止多窗口并发耗尽内存。
4. worker 执行范围扫描、增量语义解析、功能模块判定、逐事实关系投影、概览坐标和诊断。把现有布局逻辑提取为可在 Node worker 运行的纯计算部分，不依赖 React Flow 或浏览器 worker URL，并用打包版真实拓扑验证。主进程只协调、验证、提交和送轻量通知，不做源码扫描或 ELK。昂贵阶段不持有项目写锁；提交前复验源指纹、规则版本、最新 requestId 与用户修订。
5. 输入完全相同且快照有效时直接返回当前 generationId，不重新聚类、布局或批量写盘。不同输入的新代仅在完整成功后替换当前指针；中途变化、取消或失败绝不发布部分图。
6. 状态至少区分：正在迁移、迁移失败待处理、正在分析、旧概览待核验、当前图、分析失败但旧概览可见、超出支持范围。错误包含项目、阶段、文件/版本、请求和建议操作；例如代际不匹配提示“分析结果已变化，请刷新/重试”，不得误报为文件不存在或权限不足。

“部分解析成功”不是“完整准确图”：要显示总范围、已解析、失败、不支持、未解析调用、歧义调用和忽略文件数。只有约定支持范围分析结束并通过结构校验时才能将首图标为完整；不支持或无法静态确定的部分在图与诊断中明确保留。任务、上下文、审查、序列、Agent context 和导出统一从已提交代际读取，并按需生成自己的派生产物；无任何入口可直接重跑完整静态生成器。旧概览尚未验真或已知过时时，这些下游写入入口等待当前代，不能将旧代结果写成当前；如只读查看旧结果，必须带旧代标识。

## 4. 功能模块、关系和首图的确定性规则

### 4.1 先定事实，再定模块

功能区 areaId 是导航和局部聚合边界；功能模块 moduleId 是可描述、可追踪的职责单元；roleTag 仅是“API、基础支撑、数据访问”等职责标签。三者不能互相替代。首先用 AnalysisScope、包/源码根、语言配置和已解析文件限定范围；排除依赖、生成文件并标示测试与不支持文件。接着从明确声明的公开 API、命令、路由/服务、页面、作业入口、导出边界等找职责锚点；目录名、同名文件和后缀只是线索，不自动证明同一功能。根据可定位的调用、导出、注册、文件引用等事实吸收唯一相关实现。多个候选同等可信时保留待判定，共享支撑独立成模块；跨包/跨语言协作默认以关系表达，不无证据地合并文件。

基础归属采用文件唯一所有者，并显式报告单文件混合职责。若独立留出项目表明文件级归属不达标，发布前采用现有符号范围完成符号级唯一归属；一个文件可出现在多个模块的引用中，但同一符号不可被重复算作两个调用源。模块名称优先采用明确入口或声明，再用核心导出符号；证据不足时用中性结构名称并标“待判定”，禁止写入 FlowWeave 专有文案或猜测所有项目都是 Web/后台分析。

身份以稳定职责锚点和范围定义；成员微调、添加同功能的新 route 文件不能无故换 moduleId。重命名、拆分、合并必须产生 old→new lineage 与证据，供用户状态和其他引用迁移。功能区筛选、折叠、导航统一使用 areaId，roleTag 仅用于说明或按需筛选。

### 4.2 关系类型、置信度和覆盖

每条底层关系保存类型、方向、源/目标、源码位置、目标绑定依据、解析状态和独立置信度。calls 仅表示能唯一定位目标的源码 call 或等价的直接组件/render 调用；“确认”不承诺运行时必执行。HTTP request↔route 匹配是 http_contract，跨进程 invoke 是 process_invocation，另有 depends_on、reads、writes、publishes_event、subscribes_event、tests 和 manual 等类型。类型可按现有事实能力逐步支持，但不能把缺少枚举的类型压成 calls。

默认功能图只由 confirmed calls 生成跨模块边；同一模块对聚合时只合并符合该视图资格的底层事实。inferred 事实另存并在诊断/详情单独列出，不能因同组有一条 confirmed 而一并升级。默认调用精确率和覆盖率只用底层已确认调用计算；读写、HTTP、事件和手工线不进入分子分母。每条聚合线可展开到可定位的事实。无确认跨模块调用时仍展示实际模块和“未发现可确认调用”，依赖视图可用于理解静态依赖。

### 4.3 首屏图、布局与交互

worker 在同代概览中保存与视口无关的真实模块基础坐标、功能区锚点、尺寸估计与默认调用边；布局指纹包含拓扑、标签/尺寸估计规则和布局规则版本。固定输入产生稳定坐标。以清晰层级、相近职责聚拢、网格对齐、间距与无重叠为目标，循环、稀疏、密集和无边图分别验收。不能通过缩小文字或无条件折叠所有模块达成紧凑。资源/测试节点默认不挤入普通调用图；当测试本身是项目主体时可作为模块，关系叠加才加入必要资源或事件边界端点。

渲染器用实际视口与实测标签尺寸，从基础坐标确定性地选择可见模块或局部功能区聚合；小图显示全部真实模块。尺寸与视口类别变化纳入可见投影缓存键，超出估计时仅对受影响区域做有界调整并计时，不对筛选反复运行全图 ELK。聚合后的功能区显示模块数量与关系数量，并可展开；筛选仅改变可见性，展开优先复用同代基础坐标。筛选任意关系时都保留其可见边所需的真实或合成端点。若概览尚未完成坐标，不得向 UI 宣称“完整图已可用”；worker 布局和必要的渲染器局部调整都计入端到端首图时间。

工具栏保持“搜索、视图（功能调用/依赖）、折叠展开、整理布局、筛选”。“功能区”和“关系类型”归入同一个筛选面板，选项来自当前快照支持的类型；同组选择取并集，功能区与关系组之间取交集，显示命中数、生效条件及重置。无命中时区分视图不含该关系、筛选排除和折叠隐藏，不误称项目没有关系。筛选不等于布局或折叠；旧 architecture/domain/technology/execution/dependency 查看偏好在迁移器内映射到两种新视图与显示选项，旧五态枚举不进入正式运行状态。键盘、焦点、窄窗口和空态均须可用。

## 5. 所有已发布旧版本的一次性迁移

### 5.1 范围和可恢复性事实

“所有旧版本跃迁”指盘点**实际发布过的**项目数据格式，为每种已知格式提供一次性导入与验证，然后正式运行只认新协议。它不等于原样沿用旧生成结果，也不等于对未知损坏数据猜测转换。历史 Git 版本和真实样本是格式清单的依据，不能用当前类型定义推断全部历史字段。

| 旧产物 | 已知版本和现况 | 新协议动作 |
| --- | --- | --- |
| Project | v1/v2；当前扫描写 v2 | 保留项目登记、路径和用户元信息；新静态范围重新扫描 |
| Semantic Index | v1–v5；当前仅复用 v5/规则 5.0.4 | 有效内容可帮助加速导入；生成当前规则的事实缓存和 static-snapshot，不继续读旧格式 |
| ArchitectureMap | v1–v3；旧版仍用于前驱模块参考 | 只提取锚点、历史映射和不可重建审查信息；新模块从源码事实生成 |
| Canvas | v1–v6；v1–v4 当前被忽略，v5 只读，v6 混合生成/编辑 | 每版独立解码用户数据；生成图重建；手工节点、边、坐标、标注、校正和孤立项迁入 user-state |
| Task、Context、Sequence、审查、导出 | 多个版本/格式和旧 ID 引用 | 盘点用户输入与确认状态；纯派生结果标失效，按需由新 generation 重建 |
| 修改确认基线 | v1，含 graphModelVersion 和确认状态 | 保留确认决定，按可靠映射转换引用；歧义置待处理 |

Canvas v1–v4 的历史 GraphNode/GraphEdge 没有 origin 字段，不能按 origin=manual 抽取。必须对照当时的生成基线、持久字段与真实文件推断可恢复编辑；证据仍不足时保留原条目或整份画布于待处理记录，不能假装成功迁移。现有“一个成员文件重叠就自动映射”规则也不足以保证同一职责。已经被旧程序覆盖且没有副本的数据无法凭新算法复原；迁移前必须备份当前能找到的每一份历史数据，并记录这项恢复边界。

### 5.2 可执行的迁移事务

1. **封存输入**：先关闭该项目所有旧写入口，持锁恢复旧事务；枚举 .flowweave 内实际存在的旧产物、版本、哈希、大小与引用，排除 migration/、新协议文件和事务临时文件。不认可的版本或损坏文件立即将错误持久写入 migration/record.json，停在“迁移失败待处理”，禁止生成器先写空 Canvas。
2. **持久备份**：迁移前把旧原始字节与清单写入 .flowweave/migration/backups/<旧清单哈希>/；哈希复验、文件与目录持久化完成后才写备份完成标记，重试不再枚举该目录。现有 writeBatchAtomic 的临时 .bak 在成功后会删除，不能充当此备份。每个项目的迁移记录注明备份位置、大小和保留条件；至少在该项目迁移校验及恢复演练通过前不清理，后续按明确策略处理，不因删除旧代码而删除用户数据。
3. **解码与分类**：各历史版本只通过迁移器适配到统一迁移中间表示；区分可重建的静态判断与不可重建的手工位置、节点/边、文字、模块校正、审查决定、修改确认和引用。旧格式不明确时保留原文并标注理由。
4. **新建事实**：用唯一新 worker 从当前源码建立 static-snapshot 和带坐标的 graph-overview；记录输入指纹、规则版本、解析覆盖及失败项。旧模块和旧推断关系只可作为映射线索，不得直接成为新确认事实。
5. **确定性映射**：按范围、稳定入口/符号、成员交集及关系证据形成 old→new lineage；只有一对一且证据充足才自动迁移坐标、校正和引用。拆分、合并、同名不同职责或丢失源码进入待处理清单，保留原内容和候选，禁止任意择一。
6. **跨产物切换**：转换 Canvas 用户状态、修改确认基线及审查/导出等用户引用；任务、上下文和序列的纯派生结果标为旧代并按需重建。所有下游读取使用同一代际 API，不直接拼接磁盘上的 project/Canvas/architecture/context。
7. **校验并发布**：短提交锁内复验旧输入清单哈希，防止迁移期间外部或残余写者改动；比较最新 userRevision，旧修订上的映射不得覆盖期间新编辑，冲突则退出锁重映射再重试。核对备份哈希、旧编辑总数＝成功映射数＋待处理数、引用闭合、所有边端点存在、静态/概览/用户状态代际及哈希一致；以 writeBatchAtomic 提交新协议文件和成功记录，generation.json 最后发布。失败恢复旧事务，并在独立持久的 migration/record.json 保存失败阶段、路径与原因，不切回旧 UI。
8. **幂等与恢复**：迁移记录以旧文件清单哈希和目标协议标识身份；尝试开始与失败记录独立于正式 generation 持久保存，成功状态随最终事务提交。重启、重复打开、中断后重试不重复创建手工项。新协议已提交且校验通过时不再读取旧产物。恢复演练要证明可从封存数据再次得到相同用户状态与待处理清单。

项目进入新协议后，正常界面只显示新图或明确的“迁移失败待处理”页面；后者允许查看问题、导出备份和重试，不启用旧 v5 只读画布作为第二套正式运行模式。迁移历史解码器可随安装包保留以服务尚未打开的旧项目，但它们只能从明确的迁移入口调用；旧生成器、写入器、视图状态和普通消费者必须删除。待处理编辑可在新 user-state 中由用户审阅，不妨碍无歧义部分使用新系统。

### 5.3 需要冻结的历史夹具

从实际发布版本的 Git 树和匿名化真实项目各采集 Project、Semantic Index、ArchitectureMap、Canvas v1–v6、Task/Context/Sequence、审查与基线样本。每份夹具必须有原始字节、版本、用户编辑清单和期望迁移结果。现有 v4 测试样本带历史版本并不存在的 origin 字段，不能作为 v4 覆盖证明，应改用真实旧结构。还需覆盖未知版本、截断 JSON、无源码、路径重命名、模块拆并、事务中断与跨平台路径。格式尚无真实样本时标“待盘点”，不得宣称全版本已支持。

## 8. 发布验收矩阵与反例

样本至少覆盖 TypeScript、Python、Java、Go；单语言/混合、多包/单包；应用、库、CLI、任务或数据处理；显式/非显式功能边界；小中大规模；稀疏、密集、循环、无边；冷开（无 FlowWeave 缓存）、有效热开、源码变更和旧版迁移。每类包含真实项目与最小边界项目，并保留不参与调参的独立留出项目。coregist-news 仅是一项回归样本，不决定规则或唯一性能预算。

时间从目录选择完成开始，分别记录工作区可交互、首张真实模块图完成布局且可点击、有效缓存确认当前、取消完成。每个发布场景至少 20 次，保留原始数据，按项目类型和规模公布 p50/p95/最大值、峰值 RSS、首屏 IPC 字节数和渲染长任务。约 1 秒是进入工作区的交互目标，不承诺所有规模的完整图都在 1 秒内完成；完整图时间预算由 P1 基线分层冻结。微基准和“worker 已完成”不能替代画布可点击终点。

调用精确率＝人工核对正确的预测 calls / 全部预测 calls；可确认调用召回率＝检出的已标注、支持范围内可静态解析 calls / 此类标注 calls。标注必须包含未画出的调用，同时公布总调用点、未解析、歧义、失败和不支持数量。模块评审按职责一致性、名称区分度、成员合理性、碎片化与过度合并分别统计；某类项目不达标不能由总体平均掩盖。图面评估节点重叠、留白、边交叉、同拓扑坐标位移和可读字体；阈值在 P1 冻结。已知数据丢失、混代显示、类型误标和确定性错误必须为零。

以下最小反例必须成为可运行回归，而非只写在文档：

- 无调用或其他共同职责证据时，src/api/user.ts 与 src/storage/user.ts 不因同名而合成 User 模块。
- 给 src/features/users/user.controller.ts 所在职责增加 src/features/users/route.ts，不无故更换原 moduleId 或丢失坐标。
- 同模块对一条 confirmed 和一条 inferred 调用，默认线只引用 confirmed 的证据；详情保留另一条的未确认状态。
- HTTP route 契约、进程 invoke、import 不能计为直接 calls；事件叠加筛选保留必要边界端点。
- 两个功能区的小图默认展示实际模块；普通首图无无关资源和测试节点；资源/测试主体项目按规则例外。
- 重复开图在指纹尚未报告前也合并；相同输入热开不重写；新请求在旧 worker 昂贵阶段时仍能取消；所有入口不在主进程生成静态图。
- Canvas v1–v6 每版的真实结构样本、用户编辑、基线与跨产物引用迁移；未知/损坏版不被覆盖；SIGKILL 后重试幂等。
- 非 FlowWeave 的库、CLI 和数据项目中，自动角色、名称与说明只含可从该项目验证的事实，不出现 FlowWeave 专有或无依据的业务描述。

下一轮结构修正必须先处理 `groupPathForFiles` 将 `src/main/**` 等通用目录直接退回根包的问题：FlowWeave 隔离副本有 74 个模块落在同一根功能区，其中 47 个位于 `src/main/services`、13 个位于 `src/main/agents`。仅按目录或文件名前缀机械拆分会把技术层误写成功能职责；先对不同项目标注公开入口、调用社区与共享支撑的实际边界，再确定可跨项目复用的细分规则。Java 样本的同包 26 个核心文件也要以人工职责评审判断是合理内聚还是过度合并；不能仅凭模块数多或跨模块边少直接拆开。首图聚合只改变视图，不得改写模块事实、丢失关系或覆盖手工展开状态。

本轮四项遗留修复（2026-10-03）：刷新、切换标签和正常窗口关闭已接入画布保存屏障；切换及关闭的异步保存期间立即禁止画布编辑，分析中旧图只读，修改命令再次校验状态。模块文件/职责或关系输入修正会使系统评分待重新评估，布局和指导备注不会；人工风险覆写独立保存，已知系统评级随覆写保留以识别重扫后的变化，未知评级不制造误报。隐藏生成模块及资源按旧基线身份、职责和底层关系事实迁移，ID 重用、拆并或证据不足进入可审阅待处理项。详情按规范路径、代际及静态快照哈希缓存静态事实，首次并发读取共享校验/解析，读取时核对用户 revision；快照损坏仍报错。相关单测与图形冒烟覆盖自动保存窗口内的正常关闭、隔离项目写入失败时刷新或切换标签中止且画布编辑保留，以及故障解除后先保存再切换；点击到详情面板就绪的耗时已由图冒烟单次记录，但**尚无**分析期间关闭/切换的打包交互回归、详情分层 20 轮 IPC/面板测量及跨项目历史数据审阅，不能把上述实现等同 P0–P5 验收通过。
