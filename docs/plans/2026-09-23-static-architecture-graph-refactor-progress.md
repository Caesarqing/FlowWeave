## 整改结果

| 问题 | 已验证行为 |
|---|---|
| 请求乱序及混合生成工件 | 请求在项目互斥锁内登记；最近登记者唯一拥有提交权。输入快照在提交前复验，项目、索引、架构、Canvas、任务、文件上下文、确认基线和缓存使用同一生成身份，提交标记最后写入。两个真实 Electron 进程并发时，新请求提交、旧请求返回 `superseded`，16 份工件身份一致。 |
| 锁、崩溃和回滚 | Electron 与 CLI 共用项目文件锁；等待时报告存活所有者，崩溃后按事务日志恢复。真实子进程覆盖替换中断、占用锁、回滚及清理失败；最新请求失败不会让旧请求补交或覆盖旧的已提交图。 |
| 用户编辑迁移 | 生成连线指导和确认基线按稳定边 ID 或唯一迁移端点匹配；空内容和主动清空保留。拆分、合并或资源消失时，无法唯一映射的编辑进入孤儿集合。重扫及导出不会确认尚未发送的指导。 |
| Canvas v5 恢复 | 旧图先显示为只读，再尝试重扫。真实 mac-arm64 包遇到损坏的隔离 tsconfig 后仍显示旧图，项目状态说明重扫失败，编辑按钮禁用，v5 Canvas 文件字节及最近成功生成身份保持不变。 |
| Python 分支绑定 | 分支、循环和异常区域不会按文本顺序挑最后一个构造类型；合流保留候选，之后明确无条件赋值可建立唯一绑定。 |
| TS 未构建包绑定 | 输出路径映射收集所有受配置约束的真实候选。唯一候选才确定绑定；零个或多个候选分别诊断，不取扫描到的首个文件。 |
| 文件操作方向 | `copyFile` 保留来源读取与目标写入，`rename` 保留来源/目标角色；静态打开模式决定读写方向，`O_CREAT`/`O_TRUNC` 计入写入，未知模式保留未定位事实。 |
| 事件 emitter 身份 | 直接别名、导入和重导出复用原 emitter 身份；不同实例及不同通道保持分离。 |
| SQLite 与 HTTP 资源 | SQLite `prepare` 保存 SQL 与数据源但不生成表读写事实，执行事实定位到执行调用；协议相对 URL 不继承无关 `baseURL`，不能证明运行协议时不建立已确认资源。 |

四语言关系均使用真实 TypeScript/WASM 语法事实和项目作用域绑定。候选、能力限制、歧义和未解析原因不再伪装成已定位边；扫描不执行项目脚本。配置 YAML、TOML、XML 由应用内受限静态读取器处理，不引入配置解析运行依赖。
